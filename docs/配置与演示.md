# 配置与演示

在 Windows 安装 Node.js 24+ 后，把根目录 .env.example 复制为 .env。默认 preview 模式不调用模型，可以先查询“供应商采购金额汇总的口径是什么”，查看原文片段。

## SQL Server

采购事实查询需要已初始化的 Inventory 练习数据库。结构和脚本见关联项目 [Inventory-demo](https://github.com/Houstonyang/Inventory-demo)，按照其说明在独立练习环境准备数据。助手不会自动建库或重置数据。

配置 RAG_SQL_SERVER 为自己的实例地址，RAG_SQL_DATABASE 为 Inventory，RAG_SQLCMD_PATH 为已安装的 SQLCMD.EXE 路径。使用当前 Windows 账号登录；应用代码限制为固定 SELECT 模板，但不会改变账号自身权限。

运行 npm run verify:sql 可以验证连接与样例查询。脚本可能把验证成功的本机连接协议写回 .env，并在 reports 中保存本机身份与查询结果；这些文件默认不进入 Git。

## 模型问答

RAG_MODE 改为 online，填写 RAG_API_KEY，以及所用服务的 RAG_BASE_URL、RAG_CHAT_MODEL 和 RAG_EMBED_MODEL。示例配置沿用项目验收时的模型名称，实际可用性以自己的服务账号为准。

在线模式会把知识资料发送给向量接口，把问题与检索片段发送给文本模型。只导入可用于该服务的资料。不要提交 .env；模型调用失败会报告错误。

## 启动与演示

双击“启动.cmd”启动后台服务，手动打开 http://127.0.0.1:8791 。关闭浏览器不会停止服务；双击“停止服务.cmd”关闭。修改 .env 后重启服务。需要观察实时日志时用“启动前台.cmd”。

1. 查询“PO20260915001 还差多少”，核对样例库中的订购 500、实收 300、待收 200。
2. 提问“收货跟踪表有哪些查询限制”，打开来源核对口径。
3. 通过网页新建或导入 Markdown/TXT，编辑版本后保存并刷新检索。
4. 停用资料后重新提问，核对该资料不再参与检索；恢复后可再次检索。
5. 提问“列出逾期订单”，核对缺少预计到货日期时的范围说明。

知识库初始数据是个人练习资料，不代表真实企业采购数据。网页编辑会修改 data 中的文件；之后提交 Git 前应再次核对新增内容。

# 接入范围与查询口径

依据用户的 Inventory-demo GitHub README 和与其一致的本地 02、03、04 SQL 脚本。接入层只查询既有采购数据，没有实现 README 的后续规划。资料版本 1.2，补明确原查询的状态过滤与功能归属。

## 原 SQL 项目已完成的功能
原 Inventory-demo SQL 项目已有 Inventory 数据库、8 张表、基础档案与采购示例数据，以及采购明细清单、供应商采购金额汇总、收货跟踪三个只读查询。这些是原 SQL 脚本与 README 已记录的能力。

## 接入助手新增的功能
接入助手新增本地网页查询入口：按真实 OrderNo 或内部 OrderId 读取 SQL Server 的订单表头及商品明细；检索资料并由在线模型生成带引用的回答。网页新建、导入、编辑版本、停用和恢复资料也属于接入助手，不属于原 SQL 项目三个采购 SELECT 自带的功能。

## 收货跟踪表的统计口径与查询限制
实收只累计匹配当前来源订单和当前商品 GoodsId 的 PurchaseInDetail.Quantity：先通过 PurchaseIn.OrderId 匹配订单，再通过 PurchaseInId 与 GoodsId 匹配入库明细。该匹配范围内未按入库单 Status 过滤；不能表述成数据库中所有入库单都参与当前商品的实收统计。SUM 累计匹配明细，ISNULL 把无匹配入库数量转为 0；待收为订购减实收。同一订单同一商品重复订购明细仍有统计限制，没有新增审核、超收或库存校验。

## 状态与草稿订单没有明细时的数量展示
单据状态直接读取 PurchaseOrder.Status，不按数量自动修改。原三个采购查询从订单明细出发，没有匹配明细的订单不进入结果；当前样例的两张草稿因此没有数量行。这是无明细造成的，不是原查询按 DRAFT 状态排除了草稿。
接入助手另行提供按单号或内部 ID 查询真实订单表头的入口：无明细时只展示真实表头并说明没有明细，不编造计划、实收或待收数量，也不把未知数量补成 0。表头展示应归属于接入助手。

## 多商品展示
多商品订单逐行显示，不能把不同商品的数量简单相加为一个总待收数。

## 供应商采购金额汇总的口径
原查询按 SupplierName 分组，用 SUM(PurchaseOrderDetail.Amount) 合计当前订单明细中的金额，用 COUNT(DISTINCT PurchaseOrder.OrderId) 统计不同订单数；不是对明细行直接计数。金额不等于实际入库或付款金额，也没有读取订单签订时的历史金额。
该汇总查询没有按 PurchaseOrder.Status 过滤。符合原 INNER JOIN 关联条件且有匹配明细的草稿订单也可能计入；当前两张草稿没有明细所以不在结果中，不能概括成只统计正式订单或所有草稿都不统计。同名供应商仍可能合并分组。

## 暂不具备的能力
原表没有预计到货日期，不能从下单日期推断逾期。销售订单、销售出库、库存余额、库存流水、负库存、库存预警及新增业务一致性校验仍属 README 的待实现项，本次接入没有添加这些功能。

## 来源与实际连接
知识库 README 是说明快照；采购数据每次从 SQL Server 的 Inventory 数据库查询。文件夹里的 SQL 文件不是运行中的数据库。连接失败时报错，不回退到旧 SQLite 模拟数据。
